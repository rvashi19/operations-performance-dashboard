# Power BI Dashboard Setup

> **Status: built and verified in Power BI Desktop 2.160 (Microsoft Store), 2026-11-25.**
> `powerbi/Ops311Dashboard.pbip` is a Power BI Project generated by `powerbi/build_pbip.py`
> (TMSL `model.bim` + `report.json`). It was opened in Power BI Desktop, refreshed from `data/exports`, and all five
> pages rendered with values matching `reports/metrics.json` (134,348 requests, 98.3% resolution rate, median 15.3 h,
> average 275.7 h, 83.0% within the 7-day analytical target, 2,329 open, 98.899% DQ pass rate). Re-verified after the QA review: see `powerbi/validation/validation_checklist.md`. Screenshots: `powerbi/screenshots/`.
> The PNGs in `dashboard_mockups/` are earlier matplotlib mockups.

## Quick start (generated project)

1. `python -m src.pipeline --generate-reports` (writes the CSVs in `data/exports`).
2. `python powerbi/build_pbip.py` (regenerates the project; the `ExportFolder` parameter is set to this repo's absolute path).
3. Open `powerbi/Ops311Dashboard.pbip` and click **Refresh**.
4. If Desktop offers to upgrade the model to TMDL, choose **Don't upgrade** so `build_pbip.py` stays the source of truth.
5. Optional: **File > Save as > .pbix** for a single shareable file.

Built-in: 5 pages, slicers synced across pages (month, agency, complaint type, ZIP, status), theme,
TopN filters, cross-filtering (click a bar to filter the page). Not generated by code (add manually if wanted):
drill-through page, conditional formatting rules from section 8.

The sections below describe the manual alternative (PostgreSQL connector, hand-built model).

## 1. Prerequisites

1. Power BI Desktop (Windows, free from the Microsoft Store).
2. Run the pipeline so the views and CSVs exist:
   `python -m src.pipeline --full-refresh` then `python -m src.pipeline --generate-reports`.
3. For the PostgreSQL connector, Power BI Desktop includes the Npgsql provider. If it asks for one, install Npgsql
   4.0.x with "GAC installation" ticked. Otherwise use the CSV option.

## 2. Load data

1. **Home → Transform data → Manage parameters**: create `pServer` = `localhost:5433`, `pDatabase` = `ops311`,
   `pExportFolder` = full path to `data\exports\` (with a trailing backslash).
2. For each section of `powerbi/power_query.m`, create **New Source → Blank Query**, open **Advanced Editor**,
   paste the section and rename the query to the name in its header comment: `fnSource`, `fnCsv`,
   `FactServiceRequests`, `DimDate`, `DimAgency`, `BacklogMonthly`, `OpenRequests`, `DQIssues`, `DQRules`,
   `RawVsClean`, `RawVsCleanAgency`, `CleaningAudit`, `StagingInspected`.
3. Credentials: Database, user `ops`, password from your `.env`. Encryption: off (local container).
4. CSV-only mode: in each query replace `fnSource("schema","view")` with `fnCsv("<export name>")`. Export names
   match the CSV files in `data/exports`. `StagingInspected` can be replaced by a one-cell table holding 134348
   (from `reports/metrics.json` → `records_inspected`).
5. **Close & Apply**. Untick "Enable load" for `fnSource` and `fnCsv`.

## 3. Model relationships (Model view)

| From (many) | To (one) | Cardinality | Cross-filter | Active |
|---|---|---|---|---|
| FactServiceRequests[created_date] | DimDate[full_date] | *:1 | Single | **Yes** |
| FactServiceRequests[effective_closed_date] | DimDate[full_date] | *:1 | Single | No (used by `USERELATIONSHIP` in `[Requests Closed]`) |
| FactServiceRequests[agency_code] | DimAgency[agency_code] | *:1 | Single | Yes |
| BacklogMonthly[agency_code] | DimAgency[agency_code] | *:1 | Single | Yes |
| BacklogMonthly[month_end] | DimDate[full_date] | *:1 | Single | Yes |
| OpenRequests[unique_key] | FactServiceRequests[unique_key] | *:1 | Both | Yes (lets fact slicers filter the backlog) |
| DQIssues[unique_key] | FactServiceRequests[unique_key] | *:1 | Single | Yes (drill-through) |
| DQIssues[rule_id] | DQRules[rule_id] | *:1 | Single | Yes |

Then:
* Mark `DimDate` as a date table (`full_date`).
* Sort `DimDate[month_name]` by `month`, `OpenRequests[aging_bucket]` by `aging_bucket_order`, and
  `DQIssues[severity]` by `severity_order`.
* Hide key columns and `include_in_resolution_metrics` from report view.
* Create the `_Measures` table and paste the measures from `powerbi/dax_measures.dax`.
* Format: rates as percentage with 1 decimal place; hours as whole numbers; `[Record-Level DQ Pass Rate]` / `[Request-Level DQ Pass Rate]` with 2 decimal places.

## 7. Interactions

* **Format → Edit interactions.** On pages 1–3, cards are not filtered by the trend line (set to *None*) so
  headline totals stay stable when a month is clicked. The agency bar *filters* every other visual.
* Page 4: the rule bar *filters* the issue table and the trend; the donut *highlights*.
* Page 5: the RawVsClean table does not respond to the agency or complaint slicers (*Edit interactions → None*) because it is a run-level comparison. Its subtitle says so.

## 8. Conditional formatting rules

| Visual | Field | Rule |
|---|---|---|
| Page 2 matrix | Analytical Target Compliance % | Background: ≥90% `#2E7D32`, 75–90% `#F9A825`, <75% `#C62828` (or Field value = `[Target Compliance Color]`) |
| Page 2 matrix | Median Resolution Days | Data bars, navy |
| Page 3 matrix | Current Backlog | Colour scale white → `#1F4E79` |
| Page 4 agency bar | Agency DQ Affected % | Field value = `[DQ Rate Color]` (≤1% green, ≤5% amber, else red) |
| Page 5 table | Pct Difference | Font colour: red if abs > 1%, grey otherwise |
